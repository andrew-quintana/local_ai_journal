# RFC001 — Journals Infrastructure Technical Architecture

## Design Overview

This RFC defines the technical architecture for the secure local journaling infrastructure rebuild. The system provides encrypted journal storage with local AI assistance while maintaining complete privacy and data security.

### Architecture Principles
1. **Security by Design**: All components designed with security as the primary concern
2. **Privacy First**: No data leaves the local system under any circumstances  
3. **Fail Safe**: System failures result in secure, recoverable states
4. **Operational Simplicity**: Complex operations abstracted into simple user commands
5. **Modular Design**: Clear separation of concerns for maintainability

## Interface Contracts (verbatim)

### Vault Management Interface
```bash
# vault-manager.sh - Core vault operations
vault_exists() -> boolean
vault_create(size, location) -> exit_code  
vault_mount(passphrase_interactive) -> exit_code
vault_unmount() -> exit_code
vault_status() -> {mounted|unmounted|error}
vault_validate_integrity() -> exit_code
```

### Docker Stack Interface  
```bash
# docker-manager.sh - Container orchestration
docker_stack_up() -> exit_code
docker_stack_down(graceful_timeout_seconds) -> exit_code
docker_health_check() -> {healthy|unhealthy|starting}
docker_logs(service_name, lines) -> log_output
docker_cleanup() -> exit_code
```

### Session Control Interface
```bash
# Session control scripts - User-facing commands
bin/journals-up.sh -> exit_code
bin/journals-down.sh -> exit_code  
bin/journals-status.sh -> status_report
```

### Configuration Interface
```bash
# Environment configuration
VAULT_IMAGE_PATH="${HOME}/JournalsVault.sparseimage"
VAULT_MOUNT_POINT="${HOME}/Journals"
DOCKER_COMPOSE_FILE="./docker-compose.yml"
OLLAMA_MODEL="llama3.2:3b"
WEBUI_PORT="3000"
OLLAMA_PORT="11434"
```

### Docker Compose Contract
```yaml
# docker-compose.yml structure
version: "3.8"
services:
  ollama:
    ports: ["127.0.0.1:11434:11434"]  # Localhost only
    volumes: ["ollama-data:/root/.ollama"]
    
  open-webui:
    ports: ["127.0.0.1:3000:8080"]    # Localhost only
    volumes: 
      - "webui-data:/app/backend/data"
      - "${VAULT_MOUNT_POINT}:/journals:ro"  # Read-only
    depends_on: ["ollama"]
```

## Security Considerations

### Threat Model
- **Assets**: Personal journal content, AI model data, system configuration
- **Threats**: Data exfiltration, unauthorized access, system compromise
- **Mitigations**: Encryption, network isolation, access control, monitoring

### Security Controls
1. **Data Protection**
   - AES-256 encryption for data at rest
   - No persistent storage of sensitive data in containers
   - Read-only access control for AI systems
   - Secure passphrase handling without storage

2. **Network Security**
   - Localhost-only service binding (127.0.0.1)
   - Container network isolation
   - No external network access for AI processing
   - Firewall configuration recommendations

3. **Access Control**
   - File system permission enforcement
   - Container privilege restrictions
   - Service account limitations
   - User authentication for sensitive operations

### Compliance Requirements
- No sensitive data logging or monitoring
- Data retention policies for operational logs
- User consent and privacy policy compliance
- Security audit trail maintenance

## Performance and Scalability

### Resource Requirements
- **Minimum**: 8GB RAM, 10GB disk space, dual-core CPU
- **Recommended**: 16GB RAM, 50GB disk space, quad-core CPU
- **Network**: Local-only operation, no bandwidth requirements

### Optimization Strategies
- Model caching and preloading for faster response times
- Container resource limits to prevent system impact
- Efficient log rotation and cleanup automation
- Background processing for non-critical operations

### Monitoring and Alerting
- Health check endpoints for all services
- Performance metrics collection and analysis
- Resource usage monitoring and alerting
- Automated failure detection and recovery
