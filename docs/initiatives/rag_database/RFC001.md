# RFC001 — RAG Database Technical Architecture

## Design Overview

This RFC defines the technical architecture for integrating a local RAG (Retrieval-Augmented Generation) database with the existing secure journaling infrastructure. The system provides intelligent context enhancement through automated document processing, embedding generation, and semantic search capabilities while maintaining complete privacy and security.

### Architecture Principles
1. **Privacy by Design**: All processing and storage remains within the encrypted vault boundary
2. **Local-First Computing**: No external APIs or services required for any RAG functionality
3. **Seamless Integration**: Transparent enhancement of existing journaling workflow
4. **Resource Efficiency**: Optimized for personal computing environments
5. **Fail-Safe Operation**: Robust error handling with graceful degradation

## Interface Contracts (verbatim)

### Document Processing Interface
```python
# document_processor.py - Core document processing
class DocumentProcessor:
    def chunk_document(self, content: str, metadata: dict) -> List[Chunk]
    def extract_metadata(self, file_path: str) -> dict
    def validate_document_type(self, file_path: str) -> bool
    def process_document(self, file_path: str) -> ProcessingResult
```

### Embedding Interface
```python
# embedding_service.py - Local embedding generation
class EmbeddingService:
    def __init__(self, model_name: str = "all-MiniLM-L6-v2")
    def generate_embeddings(self, texts: List[str]) -> List[Vector]
    def get_model_info(self) -> ModelInfo
    def health_check(self) -> bool
```

### Vector Database Interface
```python
# vector_database.py - Database operations
class VectorDatabase:
    def store_document(self, doc: Document, chunks: List[Chunk], embeddings: List[Vector]) -> bool
    def similarity_search(self, query_vector: Vector, limit: int = 10) -> List[SearchResult]
    def delete_document(self, document_id: str) -> bool
    def get_document_status(self, document_id: str) -> DocumentStatus
```

### Context Retrieval Interface
```python
# context_retrieval.py - RAG context assembly
class ContextRetrieval:
    def retrieve_context(self, query: str, max_chunks: int = 5) -> ContextResult
    def rank_results(self, results: List[SearchResult], query: str) -> List[SearchResult]
    def format_context(self, results: List[SearchResult]) -> str
```

### File System Watcher Interface

class FileWatcher:

## Implementation Plan

### Phase 1: Database Foundation (Days 1-7)
1. **Local Supabase Setup**
   - PostgreSQL with pgvector extension deployment
   - Database schema design for documents, chunks, and embeddings
   - Connection management and health monitoring
   - Integration with vault lifecycle management

2. **Database Schema Implementation**
   ```sql
   CREATE TABLE documents (
       id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
       file_path TEXT NOT NULL UNIQUE,
       file_hash TEXT NOT NULL,
       document_type TEXT NOT NULL,
       word_count INTEGER,
       created_at TIMESTAMP DEFAULT NOW(),
       updated_at TIMESTAMP DEFAULT NOW(),
       metadata JSONB
   );
   
   CREATE TABLE chunks (
       id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
       document_id UUID REFERENCES documents(id) ON DELETE CASCADE,
       chunk_index INTEGER NOT NULL,
       content TEXT NOT NULL,
       word_count INTEGER,
       chunk_metadata JSONB
   );
   
   CREATE TABLE embeddings (
       id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
       chunk_id UUID REFERENCES chunks(id) ON DELETE CASCADE,
       vector vector(384), -- Dimension depends on embedding model
       model_name TEXT NOT NULL
   );
   ```

3. **Basic Document Processing**

   - Metadata extraction and validation
   - File type detection and filtering
   - Error handling and logging

4. **Vault Integration**

3. **Document Processing Workflow**
   ```python
   # Processing workflow
   def process_document_workflow(file_path: str) -> ProcessingResult:
       # 1. Validate document type and accessibility
       if not validate_document_type(file_path):
           return ProcessingResult.SKIPPED
       
       # 2. Extract content and metadata
       content = extract_content(file_path)
       metadata = extract_metadata(file_path)
       
       # 3. Chunk document with overlap
       chunks = chunk_document(content, metadata)
       
       # 4. Generate embeddings for each chunk
       embeddings = embedding_service.generate_embeddings([c.content for c in chunks])
       
       # 5. Store in vector database
       return vector_db.store_document(metadata, chunks, embeddings)
   ```

4. **Quality Assurance**
   - Embedding quality validation through similarity testing
   - Chunk boundary optimization for context preservation
   - Processing accuracy verification
   - Performance optimization and resource usage monitoring

### Phase 3: RAG Integration (Days 15-21)
1. **Semantic Search Implementation**
   - Vector similarity search with pgvector
   - Hybrid ranking combining semantic similarity and recency
   - Query preprocessing and optimization
   - Result post-processing and formatting

2. **Context Retrieval Service**
   ```python
   # Context retrieval workflow
   def retrieve_context(query: str, max_chunks: int = 5) -> str:
       # 1. Generate query embedding
       query_vector = embedding_service.generate_embeddings([query])[0]
       
       # 2. Perform similarity search
       results = vector_db.similarity_search(query_vector, limit=max_chunks * 2)
       
       # 3. Rank and filter results
       ranked_results = rank_results(results, query)[:max_chunks]
       
       # 4. Format context for AI consumption
       return format_context_for_ai(ranked_results)
   ```

## Security Considerations

### Threat Model
- **Assets**: Journal content, RAG database, embedding models, search queries
- **Threats**: Data exfiltration, unauthorized access, privacy compromise, model poisoning
- **Mitigations**: Vault encryption, network isolation, local processing, access control

### Security Controls
1. **Data Protection**
   - All RAG data stored within encrypted vault boundary
   - No external API calls for any RAG functionality
   - Local embedding generation with no data transmission
   - Secure database credentials and access control

2. **Network Security**
   - Database bound to localhost only (127.0.0.1)
   - No external network access for RAG components
   - Container network isolation
   - Firewall rules for additional protection

3. **Access Control**
   - Read-only access to journal documents
   - Database access restricted to RAG services only
   - File system permissions enforcement
   - Service account limitations

### Privacy Guarantees
- No sensitive data logging or external transmission
- Local processing with no cloud dependencies
- User control over all RAG functionality
- Transparent processing with user visibility

## Performance and Scalability

### Resource Requirements
- **Minimum**: Additional 2GB RAM, 5GB disk space
- **Recommended**: Additional 4GB RAM, 20GB disk space
- **CPU**: Background processing optimized for efficiency

### Performance Targets
- Document processing: <30 seconds per typical journal entry
- Search response: <2 seconds for semantic queries
- Context retrieval: <1 second for AI enhancement
- Background processing: <5% CPU usage during idle

### Optimization Strategies
- Efficient chunking strategies to minimize storage overhead
- Embedding model selection balancing quality and resource usage
- Database indexing and query optimization
- Asynchronous processing for non-blocking operations
