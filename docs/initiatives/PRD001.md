# PRD001 — Journals Infrastructure Rebuild

## Project Context

**Project**: Secure Local Journaling Infrastructure Rebuild  
**Target Users**: Privacy-conscious individuals seeking AI-assisted journaling  
**Current State**: Legacy journaling scripts with overlapping functionality, security gaps, and poor maintainability  
**MVP Scope**: Production-ready local journaling system with encrypted storage, AI assistance, and GitHub distribution readiness

## Problem & Goals

### Current Pain Points
The existing journaling infrastructure suffers from:
1. **Security Inconsistencies**: Vault management lacks atomic operations and proper error handling
2. **Operational Complexity**: Overlapping scripts with redundant logging and miswired compose calls
3. **Maintenance Burden**: Messy codebase structure prevents debugging and extension
4. **Distribution Gaps**: Not structured for reproducible deployment or sharing

### Primary Goals
- **Security-First Design**: Encrypted journal storage with localhost-only AI access
- **Operational Reliability**: Atomic operations with graceful error handling and recovery
- **Maintainable Architecture**: Clean separation of concerns with modular components
- **Distribution Ready**: Repository structure suitable for GitHub sharing and reproduction

## Implementation Approach

### Security Architecture
- **Vault Management**: APFS sparse image with interactive passphrase entry
- **Network Isolation**: Docker services bound to 127.0.0.1 only
- **Access Control**: Journal directory mounted read-only to AI containers
- **Data Protection**: No journal content logging, ephemeral AI processing

### Technical Stack
- **Container Platform**: Docker Desktop with custom compose configuration
- **AI Services**: Ollama (model serving) + Open WebUI (interface)
- **Storage**: Encrypted APFS sparse image with macOS native encryption
- **Orchestration**: Bash scripts with proper error handling and rollback

### Development Methodology
- **Documentation-First**: PRD → RFC → Implementation
- **Security-First**: Every component designed with security as primary concern
- **Testing-Driven**: Comprehensive testing at unit, integration, and system levels
- **Failure-Tracked**: FRACAS methodology for systematic failure analysis
