# PRD001 — llama.cpp Migration Initiative

## Project Context

**Project**: Migration from Ollama to llama.cpp Runtime  
**Target Users**: Cross-platform users requiring native performance optimization and Windows compatibility  
**Current State**: Ollama-based AI infrastructure with macOS-focused deployment  
**MVP Scope**: System-agnostic llama.cpp deployment with Docker baseline and native acceleration support

## Problem & Goals

### Current Pain Points
The existing Ollama infrastructure has platform limitations:
1. **Platform Dependencies**: Ollama's wrapper abstractions limit direct hardware control
2. **Windows Compatibility**: Limited native Windows support and performance optimization
3. **Performance Overhead**: Additional abstraction layers impacting inference speed
4. **Hardware Utilization**: Suboptimal GPU acceleration across different hardware configurations
5. **Deployment Complexity**: Platform-specific optimization requires Ollama-specific knowledge

### Primary Goals
- **Cross-Platform Compatibility**: Native performance on macOS (Metal), Linux (CUDA), and Windows (CUDA/DirectML)
- **Performance Optimization**: Direct hardware acceleration without runtime overhead
- **Standardized Deployment**: Docker-based baseline with consistent behavior across platforms
- **API Compatibility**: Preserve existing OpenAI-compatible API endpoints
- **Model Portability**: Standardize on GGUF format for consistent model behavior

## User Stories & Acceptance Criteria

### Cross-Platform Performance
**As a** user on Windows/Linux/macOS  
**I want** native AI inference performance optimized for my hardware  
**So that** I get the best possible speed and efficiency regardless of platform

**Acceptance Criteria:**
- [ ] Native Metal acceleration on macOS with >90% GPU utilization
- [ ] CUDA acceleration on Windows and Linux with full GPU memory usage
- [ ] Consistent API endpoints across all platforms
- [ ] Performance meets or exceeds current Ollama benchmarks

### Model Standardization
**As a** developer managing AI models  
**I want** consistent model format and behavior across platforms  
**So that** deployment and testing are predictable and reproducible

**Acceptance Criteria:**
- [ ] All models standardized to GGUF format
- [ ] Quantization levels consistent across platforms (Q4_K_M, Q3_K_M)
- [ ] Model conversion pipeline documented and automated
- [ ] Version-locked model checksums for consistency validation

### API Compatibility
**As a** developer using the AI infrastructure  
**I want** existing API calls to work without modification  
**So that** migration is transparent to dependent systems

**Acceptance Criteria:**
- [ ] OpenAI-compatible `/v1/chat/completions` endpoint preserved
- [ ] JSON tool-calling functionality maintained with 100% validity
- [ ] Response format and timing characteristics preserved
- [ ] Fallback mechanism to Ollama for compatibility validation

### Development Workflow
**As a** developer testing and debugging  
**I want** portable baseline testing with Docker  
**So that** I can validate functionality before platform-specific optimization

**Acceptance Criteria:**
- [ ] Docker-based CPU inference for consistent baseline testing
- [ ] Automated benchmark suite for performance validation
- [ ] A/B testing framework for Ollama vs llama.cpp comparison
- [ ] Clear documentation for local development setup

## Metrics / Guardrails

### Performance Benchmarks
- **Inference Speed**: Tokens/second ≥ current Ollama performance at same quantization
- **Time to First Token (TTFT)**: <2 seconds for typical prompts
- **Latency P50/P95**: ≤ current Ollama latency at comparable settings
- **Memory Efficiency**: VRAM/RAM usage ≤ 110% of current Ollama usage

### Quality Validation
- **JSON Tool-call Validity**: 100% success rate on existing test suite

## Implementation Approach

### Model Standardization Strategy
- **GGUF Conversion**: Automated pipeline for HF safetensors → GGUF conversion
- **Quantization Levels**: Q4_K_M as primary, Q3_K_M for speed testing
- **Checksum Validation**: SHA256 verification for model consistency
- **Storage Management**: Organized model repository with metadata

### Deployment Architecture
- **Docker Baseline**: CPU-only inference for development and testing
- **Native Builds**: Platform-specific optimization with direct hardware access
- **Configuration Management**: Environment-based runtime selection
- **Monitoring Integration**: Performance metrics and health checking

### Testing Framework
- **Benchmark Suite**: Standardized prompts for journaling and MCP tasks
- **Performance Metrics**: Automated collection of speed and quality metrics
- **Compatibility Testing**: API endpoint validation and response comparison
- **Regression Testing**: Automated validation against Ollama baseline
